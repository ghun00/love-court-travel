# 러브코트 홈페이지 전환 디자인 스펙
> 2026-09-04 브레인스토밍 확정본. 대기명단 랜딩페이지 → 상품 확인·예약 홈페이지 전환.
> 이 문서는 확정 스펙이나, 구현 중 대표 판단으로 수정될 수 있다 (수정 시 이 문서를 갱신한다).

---

## 0. 배경 및 목표

- 기존: 대기명단 등록 단일 목적의 원페이지 랜딩 (02_랜딩페이지_기획안.md).
- 전환: 유저가 트립 상품을 확인하고 **계약금 결제까지 온라인으로** 완료하는 홈페이지.
- 타겟: **혼자 여행 오는 2030세대**. 소규모 프리미엄. 과시욕 욕구를 스냅 사진 가치로 해결.
- 상품 상태: 확정 트립 1개(세부 일정은 판매 시점에 확정) + 준비중 트립 여러 개를 카드로 노출해 "하나만 하는 서비스가 아니다"라는 규모감 표현.
- 결제: 확정 상품 계약금. PG 직접 연동 예정이나 **지금은 UI 구조만 만들고 결제 버튼은 비활성** (연동 시 페이지 구조 변경 없도록).

## 1. 확정된 의사결정 요약

| 항목 | 결정 |
|---|---|
| 최종 전환 액션 | 계약금 온라인 결제 (연동 전까지는 신청 제출 + 결제 안내) |
| 결제 성격 | 확정 상품 계약금 |
| 결제 수단 | PG 직접 연동 예정, 현재는 구조만 |
| 페이지 구조 | 홈 + 트립 상세 분리 ("원 플래그십" 구조) |
| 색 톤 | 밝은 프리미엄 유지 (기존 토큰), 클투 커머스 문법만 차용 |
| 스냅 사진 자산 | 아직 없음 — 플레이스홀더로 구조 구축, 촬영 후 교체 |
| 기존 3패널(Move/Connect/Remember) | 폐기 → 콤팩트 가치 카드로 전환 |
| 스테이징 | **배포 전까지 새 홈페이지는 `/test` 경로 하위**, 기존 랜딩 `/` 유지 |

## 2. 페이지 맵 & 전환 동선

```
/                      기존 랜딩 (배포 전환 시점까지 그대로 유지)
/test                  새 홈
/test/trips/{id}       트립 상세 (확정 트립만 활성)
/test/trips/{id}/book  예약 플로우
```

- 공개 전환 시 `/test` 하위 경로를 루트로 스왑하고 기존 랜딩은 제거 또는 보관.
- 모든 CTA는 확정 트립 상세 → 예약으로 수렴.
- 모바일 하단 고정 CTA 바 + 데스크톱 우상단 고정 버튼 유지, 문구는 "트립 예약하기" 계열로 변경.

## 3. 홈 섹션 구성

1. **히어로** — 풀블리드 사진(기존 자산 재사용) + 오버레이. 히어로 안에 확정 트립 카드형 배너("NOW OPEN — {목적지} 테니스 트립 · {기간} · 8자리") → 클릭 시 상세. 카피는 타겟 선언형("혼자 와도 되는 게 아니라, 혼자 오라고 만든 테니스 여행" 계열) — **초안이며 최종 카피는 대표 확정**.
2. **러브코트 트립에서는 (가치 카드 4개)** — 밝은 배경 콤팩트 카드 그리드:
   ① 전문 스냅 작가 동행 (대표 가치, 첫 번째 고정)
   ② 귀찮은 건 전부 러브코트가 (코트 예약·이동·식사)
   ③ 매일 최소 2시간 테니스
   ④ 자유시간 보장
3. **트립 프로그램** — 확정 트립 1개는 와이드 카드(사진 + "모집중" 그린 배지 + 목적지·기간·가격 + 자세히 보기). 준비중 트립 2~3개는 작은 카드(디새추레이트 사진 + "준비중" 그레이 배지, 상세 없음 → "오픈 알림 받기" 간단 폼으로 리드 수집).
4. **스냅 섹션** — "여행이 끝나도 남는 장면". 스냅 3~4장 그리드(플레이스홀더 → 촬영 후 교체). 과시욕 트리거 카피 방향: "친구들이 물어볼 사진".
5. **대표 스토리** — 기존 내향인 스토리 축약 재사용 (후기 0개인 현재 유일한 신뢰 자산).
6. **FAQ 4~5개** — "혼자 가도 어색하지 않나요?", "테니스 못 쳐도 되나요?", "환불 규정은?" 등 예약 직전 불안 제거.
7. **마무리 CTA + 푸터** — 기존 푸터 재사용.

## 4. 트립 상세 페이지

1. 상단: 풀블리드 사진 + 트립명·목적지·기간 + "8자리 중 N자리" + 가격(계약금/총액 병기). 예약 CTA 고정(모바일 하단 바 / 데스크톱 사이드 또는 우상단).
2. 이 트립에서 하는 것: 하루 흐름 타임라인 + Day별 상세 일정 아코디언.
3. 포함/불포함 2컬럼 리스트 (항공권 불포함 명시).
4. 코트 & 숙소: 사진 2~3장 + 짧은 설명.
5. 스냅 안내: 작가 동행·보정본 제공 등 구체 조건.
6. 모집 조건: 정원 8명, 구력, 혼자 참가 비율 등 불안 제거 정보.
7. **환불 규정** — 결제 전 반드시 노출되는 위치. 필수 섹션.
8. 예약 CTA → `/test/trips/{id}/book`

## 5. 예약 플로우

한 페이지 스텝형, 백엔드 없이 시작:

- **Step 1 신청 정보**: 이름, 연락처, 인스타(선택), 테니스 구력, 동행 여부. 수집은 Tally 백엔드(자체 스타일 폼 UI).
- **Step 2 결제**: 주문 요약 카드, 금액, 약관 동의 체크까지 전부 구현. PG 연동 전에는 결제 버튼 대신 "계약금 결제 안내를 카카오톡으로 보내드려요" + 완료 처리. 연동 시 버튼만 활성화.
- **Step 3 완료**: 완료 메시지 + 인스타 팔로우 유도.

## 6. 비주얼 디자인

- 토큰 유지: `--bg #FAF8F4`, `--green #1F4D36`, `--clay #FD4A01`, `--ink #111`, Pretendard, 코너 16px. 무드: 따뜻한·프리미엄·차분한 (01_디자인_방향.md 계승).
- 커머스 문법 추가: "모집중"(그린)/"준비중"(그레이) 배지, 가격·잔여석 표기, 카드 그리드. 클투식 포스터 그래픽·HOT 배지 남발 금지 — 프리미엄 유지 원칙.
- 준비중 카드: 사진 디새추레이트 + 그레이 배지로 확정 트립과 위계 구분.
- 제약 계승: 인스타 인앱 브라우저 90%, 모바일 390px 우선, 3D/WebGL/영상 배경 금지, 모션은 페이드인·저강도 패럴랙스 수준, prefers-reduced-motion 존중, 팝업·챗봇·모달 금지.

## 7. 기술 구조

- React + Vite + Tailwind 유지. 신규 의존성은 `react-router-dom` 하나만.
- **`src/data/trips.ts` 단일 데이터 파일**: id, 목적지, 트립명, 기간, 가격(계약금/총액), 상태(`open`/`coming`), 정원/잔여석, 일정, 포함/불포함, 사진 경로. 카드·상세·예약 전부 이 파일을 읽음 — 트립 추가/수정 = 파일 하나 편집.
- 재사용: Topbar, Footer, CtaButton, BgMedia, hooks(useReveal 등). Waitlist·ValuePanels·Story는 새 구성으로 교체/개편.
- 라우팅: `/` 기존 랜딩 그대로, `/test/*`에 새 홈페이지. SPA fallback 필요 시 배포 환경(현 정적 호스팅) 설정 확인.
- 추적: GA4 이벤트 퍼널 — 프로그램 카드 클릭 → 상세 진입 → 예약 시작 → 신청 제출.

## 8. 콘텐츠/자산 준비 목록 (대표 담당)

- 확정 트립 정보: 목적지, 일정, 가격(계약금·총액), 포함/불포함, 코트·숙소 정보, 환불 규정
- 준비중 트립 2~3개: 목적지명 + 대표 사진 1장씩
- 스냅 사진: 촬영 후 교체 (그 전까지 플레이스홀더)
- 최종 카피 확정 (히어로, 가치 카드, 스냅 섹션, FAQ)
